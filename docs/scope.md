\# SentinelX — Project Scope



\## 1. Project Scope



SentinelX is an advanced Security Operations Center (SOC) platform designed to collect, normalize, detect, correlate, investigate, and contextualize security events from multiple telemetry sources.



The project focuses on building an integrated security-analysis workflow that helps SOC analysts move from individual alerts toward contextual incident investigation and evidence-based decision making.



\## 2. In Scope



\### 2.1 Security Telemetry Collection



SentinelX will collect security telemetry from:



\* Wazuh endpoint security monitoring

\* Suricata network security monitoring

\* Controlled security-laboratory test environments



\### 2.2 Event Normalization



The platform will transform heterogeneous telemetry into a common internal event structure containing relevant fields such as:



\* Timestamp

\* Event source

\* Host

\* User

\* Event category

\* Severity

\* Source and destination information

\* Process or activity information

\* Raw evidence reference



\### 2.3 Detection



SentinelX will provide configurable detection capabilities for identifying suspicious security activity from normalized events.



\### 2.4 Event Correlation



The platform will correlate related events using contextual factors such as:



\* Time

\* Host

\* User

\* Network relationships

\* Event types

\* Detection relationships



\### 2.5 Incident Generation



Related security activity can be grouped into incidents containing:



\* Detection findings

\* Related telemetry events

\* Risk information

\* Evidence

\* Timeline information

\* MITRE ATT\&CK mappings

\* Investigation results



\### 2.6 Attack Story Reconstruction



SentinelX will reconstruct related events into chronological attack stories to help analysts understand how suspicious activity developed over time.



\### 2.7 MITRE ATT\&CK Integration



The system will map relevant detected behaviors to MITRE ATT\&CK tactics and techniques where sufficient evidence exists.



\### 2.8 Risk Assessment



SentinelX will calculate contextual risk assessments using available security evidence and contextual relationships.



\### 2.9 AI-Assisted Investigation



The platform will provide AI-assisted investigation based on structured security evidence generated by the SentinelX analysis pipeline.



AI functionality will support:



\* Security-event interpretation

\* Incident summarization

\* Evidence analysis

\* Investigation assistance

\* Analyst-oriented explanations

\* Response recommendations



AI output will be treated as analyst decision support rather than an autonomous security authority.



\### 2.10 Threat Hunting



Authorized SOC analysts will be able to search historical security telemetry to investigate suspicious behaviors and identify potential attack patterns.



\### 2.11 Incident Investigation



The platform will provide an investigation workflow allowing analysts to review:



\* Alerts

\* Incidents

\* Evidence

\* Event timelines

\* Affected hosts

\* Users

\* MITRE ATT\&CK techniques

\* Risk assessments

\* AI investigation results



\### 2.12 Analyst Response Support



SentinelX will provide evidence-based recommendations that help analysts determine appropriate investigation, containment, and remediation actions.



\## 3. Out of Scope



The following capabilities are outside the primary scope of the project:



\### 3.1 Autonomous Attack Prevention



SentinelX will not independently perform offensive or destructive actions against systems.



\### 3.2 Fully Autonomous Incident Response



The system will provide recommendations and analyst support rather than automatically executing high-impact response actions.



\### 3.3 Large-Scale Commercial SOC Deployment



The project will be developed and evaluated in a controlled laboratory environment and is not intended to represent a production-scale enterprise SOC deployment.



\### 3.4 Malware Development



Development of malware, ransomware, destructive payloads, or similar offensive software is outside the project scope.



\### 3.5 Unauthorized Security Testing



The system will only be evaluated against systems and environments that are explicitly authorized for testing.



\### 3.6 Complete Threat Intelligence Platform



SentinelX may consume threat-intelligence information, but building a complete commercial-scale threat-intelligence platform is outside the primary scope.



\## 4. Target Users



The primary target users are:



\* SOC analysts

\* Security operations teams

\* Incident responders

\* Cybersecurity students and researchers

\* Security administrators



\## 5. Deployment Scope



The initial SentinelX implementation will operate within a controlled cybersecurity laboratory containing:



\* SentinelX backend

\* SentinelX frontend

\* PostgreSQL database

\* Wazuh security monitoring

\* Suricata network monitoring

\* Controlled endpoint and network telemetry



\## 6. Project Boundaries



SentinelX focuses on \*\*security visibility, detection, correlation, investigation, contextual analysis, and analyst decision support\*\*.



The project does not attempt to replace human SOC analysts. Instead, it aims to improve their ability to understand related security activity and prioritize investigations using contextual evidence.



\## 7. Scope Limitations



The project will be evaluated using controlled security scenarios and representative telemetry because the available development timeframe and laboratory resources do not represent the full complexity of a large enterprise SOC.



The architecture will nevertheless be designed to remain modular and extensible for future integrations and larger deployments.
